# 专注模块收缩为顶部状态条设计

## Goal

将当前占据主窗口大面积区域的专注卡片，重构为顶部一条常驻的极简状态条，并把完整控制收纳进按需展开的二级面板。

目标不是削弱番茄钟能力，而是纠正其在主窗口中的视觉权重，使其重新符合 Rhythm “桌面角落常驻、低打扰、轻量扫读”的产品定位。

## Background

当前番茄钟 UI 采用完整卡片常驻展示，包含：

- 阶段 badge
- 设置按钮
- 大号倒计时
- 循环与今日统计
- 关联事项信息
- 事项选择器
- 清空按钮
- 开始 / 暂停 / 跳过 / 重置操作

这套结构虽然功能完整，但直接导致两个问题：

- 主窗口上半区被专注模块占据，压缩了清单作为主内容的可见面积。
- 专注模块的形态更像“第二张主卡片”，而不是一个桌面部件中的轻量状态入口。

因此这次设计的核心不是再压缩几像素，而是改变信息层级：常驻区只负责显示状态，控制与配置都降级到二级层。

## Requirements

- 专注模块在主窗口中只占据顶部一小块区域。
- 常驻区域始终极简，不承担直接控制操作。
- 常驻区域点击后可展开完整控制层。
- 状态条默认显示三类信息：当前阶段、上下文信息、剩余时间。
- 上下文信息需要按状态动态切换，不采用表单式字段文案。
- 展开层复用现有番茄钟能力，不牺牲开始、暂停、继续、跳过、重置、关联事项、设置入口。
- 空闲时保持低存在感；运行中才适度强调时间信息。

## Out of Scope

- 不调整番茄钟状态机、会话恢复、统计口径和提醒语义。
- 不新增新的番茄功能，例如历史统计、目标、热力图、悬浮窗。
- 不改变事项与番茄钟的弱绑定语义。
- 不在本设计中讨论动画细节、通知样式和托盘菜单结构。

## Approaches Considered

### 方案 A：保留现有卡片，只做缩高

把现有卡片压扁，例如减少按钮高度、收紧间距、缩小时间字号。

优点：

- 改动最小。

缺点：

- 只是“更紧的大卡片”，问题根源没变。
- 设置、选择器、控制按钮仍然长期占据主界面。
- 视觉上依然像第二个主内容区块。

### 方案 B：顶部状态条 + 点击展开面板

默认只保留一条极简状态条，点击后在主窗口内部就地展开完整番茄控制面板。

优点：

- 同时满足低打扰常驻与完整功能可达。
- 常驻态与操作态职责清晰。
- 最大限度释放清单区域。

缺点：

- 需要重新梳理 UI 层级与交互状态。

### 方案 C：顶部状态条 + 外部弹窗

默认只显示状态条，点击后弹出独立悬浮窗承载控制面板。

优点：

- 主窗口最干净。

缺点：

- 交互被拆成两个容器，破坏 Rhythm 的单体部件感。
- 与现有“主窗口内完成主要交互”的习惯不一致。

## Recommendation

采用方案 B：顶部状态条 + 点击展开面板。

这是最平衡的方案，因为它把专注模块拆成两个清晰层次：

- 常驻态：只负责扫读状态
- 展开态：负责短时间控制

这样番茄钟仍然是主功能之一，但不再长期霸占主窗口。

## Design

### 常驻态：顶部单行状态条

专注模块收敛为一条常驻状态条，位于日期与进度信息右侧或其下方上部可用区域，整体视觉上更接近“系统状态槽”，而不是内容卡片。

建议从左到右分为三段：

1. `状态点 + 阶段文案`
2. `按状态切换的次要信息`
3. `倒计时 + 展开箭头`

状态条不出现任何直接操作按钮，不放设置按钮，不放选择器，不放统计字段名。

### 状态条文案规则

左侧主状态文案固定为短词，不写成长句：

- 空闲：`准备专注`
- 专注中：`专注中`
- 短休息：`短休息`
- 长休息：`长休息`
- 暂停：`已暂停`

中间次要信息按状态切换：

- 空闲：`可开始 25 分钟`
- 专注中：显示关联事项名；若无则显示 `未关联事项`
- 短休息：`上一轮已完成`
- 长休息：`已完成 4 轮`
- 暂停：优先显示关联事项名；若无则显示剩余时间摘要

右侧只显示纯时间值，例如：

- `25:00`
- `24:12`
- `05:00`

不额外附带“剩余”“倒计时”“本轮”等说明文字。

### 状态条视觉规范

状态条的目标是低打扰，但必须支持一眼扫读。

建议约束：

- 高度控制在 `56px - 68px`
- 背景仅比窗口底色轻微抬起一层
- 保留圆角，但边框与阴影要显著弱于当前番茄卡片
- 左侧阶段文案建议 `16px - 18px` 半粗
- 中间次要信息建议 `12px - 13px` 低对比度
- 右侧时间建议 `24px - 28px` 粗体，但不得再使用当前主标题级视觉
- 状态点使用小尺寸色点，而不是 badge 或大面积色块

颜色语义建议：

- 空闲：灰蓝
- 专注中：蓝
- 短休息：绿
- 长休息：青
- 暂停：橙灰

颜色仅用于小范围语义提示，不应把整条状态条做成高饱和色块。

### 展开态：就地展开的二级面板

点击状态条后，在其下方就地展开完整控制面板，而不是恢复原先的大卡片常驻形态，也不弹出独立窗口。

展开层与主窗口同宽，属于状态条的二级层，仅在需要操作时出现。

面板建议固定为三个区块：

1. `主计时区`
2. `当前事项区`
3. `控制区`

### 主计时区

主计时区展示更完整的专注信息，包括：

- 更大的倒计时
- 当前阶段说明，例如 `第 1 轮专注中`
- 今日专注进度，例如 `今日已完成 0 个番茄`

这部分是展开态的主视觉中心，但只在点击后出现，不再长期占据首页。

### 当前事项区

事项区保留一条关联事项选择能力，但弱化成上下文辅助，不再撑开一大块表单区。

建议规则：

- 空闲时允许选择或清空关联事项
- 运行时默认只展示当前关联项，不鼓励中途频繁改动
- 若需要更改，可通过次级入口进入，而不是把选择器长期暴露在常驻态

### 控制区

控制区保留现有核心能力，但重新做主次分层。

建议改为：

- `1 个主按钮`
- `2 - 3 个次级文字按钮`

状态映射如下：

- 空闲态：主按钮为 `开始专注`
- 运行态：主按钮为 `暂停`
- 暂停态：主按钮为 `继续`
- `跳过` 与 `重置` 永远为次级操作

`设置` 从常驻区移出，放到展开层右上角或右下角，避免在首页长期占位。

### 交互原则

- 常驻区负责扫读，不负责控制。
- 展开层负责短时操作，不负责长期占位。
- 空闲态尽量安静，运行态再增强时间可见性。
- 点击状态条是唯一主入口，避免出现多个竞争入口。
- 关闭展开层后，主窗口立即恢复为紧凑状态。

## Migration Notes

从现有实现迁移到新设计时，建议保持领域逻辑不变，只调整 ViewModel 暴露层级与 XAML 结构。

优先保留：

- `PomodoroViewModel` 的状态与命令语义
- 当前计时、跳过、重置、恢复逻辑
- 当前关联事项与配置能力

主要改动应集中在：

- `MainWindow.xaml` 中番茄模块的布局重构
- 可能新增 `IsExpanded` 一类的 UI 状态
- 常驻态与展开态的数据投影与文案映射

## Testing

手动验证至少覆盖：

- 常驻态高度明显小于当前番茄卡片
- 空闲态不显示控制按钮、选择器、设置按钮
- 点击状态条可展开完整控制层
- 展开后仍能完成开始、暂停、继续、跳过、重置
- 关联事项在空闲态可选，在运行态默认只展示当前项
- 不同阶段下状态条中间文案正确切换
- 长时间运行时，状态条不会压过清单成为主要视觉焦点

## Risks

- **压缩过度**：如果状态条做得太像标签，用户会忽略它可点击。需要保留轻微的进入暗示，例如时间区后的箭头。
- **展开层回潮**：如果展开层继续塞满按钮、字段名和大面积表单，它只是把旧问题延后暴露。需要严格控制展开层节奏。
- **状态文案混乱**：如果中间次要信息规则不稳定，用户会难以形成扫读习惯。需要固定状态到文案的映射。
- **视觉语言分裂**：如果状态条与展开层风格差异过大，会像两个不相关组件。两者应共享基础配色与圆角体系。

## Rollout Notes

建议按以下顺序落地：

1. 先把现有番茄卡片拆成“常驻条”和“展开层”两部分。
2. 再补充状态条专用文案映射与颜色语义。
3. 然后调整展开层中的按钮主次关系与设置入口位置。
4. 最后做整窗高度、间距和清单可见面积的人工校验。
